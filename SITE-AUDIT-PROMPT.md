# Full-site audit prompt — seattledogparkdata.com

> Paste this to a fresh Claude Code session at the repo root. Goal: make every
> number, calculation, and statement on the site **airtight, reproducible, and
> consistent across pages** — with special care for how we describe **funded vs.
> hired vs. deployed** enforcement staffing. Read `CLAUDE.md` first.

---

## Mission

Audit the entire public site (`docs/*.html`) plus the data and scripts behind it.
For every load-bearing number and claim, confirm it (a) traces to a primary
source, (b) is arithmetically correct and reproducible from committed scripts,
and (c) is stated **identically and fairly** everywhere it appears. Pay special
attention to the staffing-framing invariant below — the most error-prone area.

## How to run (multi-agent fan-out)

Use the Workflow tool (or spawn subagents). Structure:

1. **Per-page readers** — one agent per public page: `index.html`,
   `part1-the-gap.html`, `part2-access.html`, `part3.html`, `enforcement.html`,
   `budget.html`, `peer-cities.html`, `opinion.html`, `updates.html`. Each
   extracts every number/claim with its `file:line`, what it asserts, and the
   source it links. (Skip `mockup-*.html`, `mockups.html`, `print.html`.)
2. **Per-dimension auditors** (run against the whole corpus): (A) numbers→source,
   (B) calculations reproduce, (C) reproducibility/build-chain, (D) staffing
   framing, (E) cross-page consistency, (F) links/sources, (G) charts vs prose vs
   alt-text, (H) dates/temporal/partial-year, (I) house-style/formatting,
   (J) stale-claims sweep. (Dimensions defined below.)
3. **Synthesizer** — reconcile findings, dedupe, resolve cross-page
   contradictions (which value is correct, per primary source), severity-rank,
   and produce one report.

Adversarially verify each substantive finding before reporting it (a second
agent tries to refute it) so the report contains no false positives.

## Ground rules

- **Fix vs report:** **Fix mechanical issues directly** — broken/oversized
  links, typos, number-formatting drift, a stale number with a single
  unambiguous correct value, alt-text that contradicts its chart. **Report (do
  not change)** anything touching wording, framing, an argument, `opinion.html`
  voice, or any judgment call or ambiguous correct value.
- **Generated files — never hand-edit.** `docs/enforcement.html` is generated by
  `scripts/build_enforcement_page.py` from `scripts/enforcement_page_data.json`.
  To change it, edit the builder/inputs and re-run. `docs/data/*` is mirrored by
  `scripts/sync-data.sh`. The PDF is built by `build-pdf.mjs`. Full list in
  `CLAUDE.md` → "Generated files." All other HTML pages are hand-maintained.
- **After any fix:** re-run `.venv/bin/python scripts/build_enforcement_page.py`
  (if the builder changed), then **both** verifiers — `.venv/bin/python
  scripts/verify_enforcement_data.py` and `.venv/bin/python
  scripts/verify_site_data.py` (each must print `ALL CHECKS PASSED`) — and
  `bash scripts/sync-data.sh` (if any `data/*.csv` changed). The enforcement
  builder must be **idempotent** (second run = no diff).
- **Cite-everything:** every factual claim must link a primary source. Flag any
  bare number without one.
- Don't bump site-wide dates, the editorial signature, `CHANGELOG`, or
  `updates.html` — that's a separate, human-approved step.

## The staffing-framing invariant (CRITICAL — most error-prone)

Three distinct concepts must never be conflated; every statement must use the
right one:

- **Funded / approved** — what the Park District authorized. Three ACO IIs since
  the **2023** MOA; FAS-side max **$454,652/yr** (2023) → **$528,279/yr** (2026
  MOA, wage re-pricing). This is an *authorization*, not spending.
- **Hired / filled** — bodies actually employed. As of **April 2026, one** of the
  three positions was filled (the long-standing officer); the two added in 2023
  were still being hired (Axios). There is always exactly **one** — never write
  "about one."
- **Deployed** — time the filled officer(s) actually spend on off-leash park
  patrol. Even the one filled officer isn't 100% on this (parks were ~**33%** of
  these officers' calls for service in 2021).

**Rules the whole site must obey:**
1. Measure **output and cost-per-citation against staffing that actually existed
   (~1 officer)** — never against the funded three. "Cost per citation rose"
   because output fell against a ~constant one-officer cost; it is NOT because
   spend tripled.
2. Never imply the city "tripled cost/output and got nothing." The funded three
   isn't deployed; the added officers "largely don't exist yet."
3. **Actual spend ≈ one officer (~$176K) today**, billed on hours worked; it
   rises toward $528,279 only **as the approved positions fill**. Going forward,
   more officers won't raise citations much because the cap is **authority**
   (can't compel ID), not headcount.
4. The SPR-side patrol partner changed from **net-new Facilities Maintenance
   Workers** (2023 model) to **existing/retasked Park Rangers** (2026 MOA) — so
   the 2026 pairing adds little net staffing. **No phantom "additional ranger
   cost."** SPR-side cost is undocumented (PRR #10 pending).
5. Retire any surviving overclaims: "3× scale-up in officer-hours," "even at 3×
   staffing," "tripled cost," "$700K–$1M all-in," "about one patrols."

Flag every sentence on every page that violates these.

## Audit dimensions (the checklist)

**A. Numbers → source.** Every load-bearing number links a primary source that
actually contains it. Open the linked source where feasible; flag bare numbers.

**B. Calculations reproduce.** Recompute every derived figure from its stated
inputs: cost-per-citation, recovery %, per-FTE, basis points, sq-ft-per-dog,
residents-per-OLA, the 0.06% land/budget shares, the 22%-of-combined, the
funded-vs-attributable band ($300K–$376K), the 14.6×/39× facilities ratios, the
$3.30M cumulative. Note any that don't reconcile.

**C. Reproducibility / build chain.** Run the builders + **both** verifiers
(`verify_enforcement_data.py` for enforcement numbers, `verify_site_data.py` for
budget/peer-city/walkshed/access numbers — each must pass). Confirm the
enforcement builder is idempotent. **Gotcha:**
`enforcement_page_data.json` is committed source the page renders from; it is
**not** auto-generated from the CSV and verify does **not** cross-check it — so
confirm the JSON `year_trend`, `data/enforcement-year-metrics.csv`, and the
`build_enforcement_metrics.py` model all agree (esp. the 2026 row: funded
528279, attributable/traceable 152399, aco_fte 1.0). Confirm `docs/data/*`
mirrors `data/*`.

**D. Staffing framing.** Apply the invariant above to every page. This is the
priority dimension.

**E. Cross-page consistency.** Any figure stated on >1 page must match exactly
and be phrased compatibly (e.g., $528,279; 7,015; 150,000; 0.06%; 11.7%; OLA
count 14; acreage 30.7; "485+ parks" vs "460 parks" vs "6,414 acres" — confirm
these park-count/acreage figures are consistent everywhere). Internal `#anchor`
links resolve (note: enforcement display-numbers were merged but section IDs
`finding-02`/`finding-07` etc. are kept for back-compat — verify every internal
and inbound link still lands).

**F. Links & sources.** No 404s; MOA/PRR blob links resolve to files that exist
in the repo; the Axios link uses the live canonical URL (not the dead
`more-paw-patrols` slug); seattle.gov/SMC/TPL links valid.

**G. Charts vs prose vs alt-text.** Chart data matches the prose around it and
the CSV behind it; each `aria-label`/alt text describes the *current* data
(e.g., the funded-vs-deployed chart, the −80% stat, the 2022 budget point).

**H. Dates / temporal / partial-year.** "as of April 2026", "April 2026 Axios",
masthead "JUNE 2026", editorial "June 2026" — all internally consistent. 2026 is
partial (through Apr 17, ~29%); confirm every chart/figure marks or excludes it
correctly and annualization caveats are present.

**I. House style / formatting.** Per `CLAUDE.md`: spell out sub-$1M and counts
($100,000; 150,000), millions as `$X.XXM`; no `($K)/($M)` in table headers;
acronyms defined on first use per page; `.lead/.note/.fineprint` type classes
(no inline font-size). Number-formatting drift (tabular-comma issues, etc.).

**J. Stale-claims sweep.** Grep for and flag any survivor of: `3× scale-up`,
`even at 3× staffing`, `tripled cost`, `$700,000 to $1M` / `$700K–$1M`,
`about one`, `one patrols`, `funded staffing tripled`, the old `$475,100`/
`$614,300` proposed budget figures, `$3.34M`, `2027` MOA-term claims that should
now reflect the 2026 re-up.

## Output

Write `AUDIT-FINDINGS.md` at repo root:
- **Mechanical fixes applied** — table: file:line · what · before → after.
- **Substantive findings (report only)** — severity (P0 wrong/contradictory
